Race 001 — 三个 agent 并行搜索同一契约的解空间

契约 deprecation-cascade

三个 Opus agent、三份隔离副本、同一份不可变契约、同一个赛前写死的验收门。评审协议在任何解存在之前预注册入库；幸存者去署名后按五条 rubric 成对盲评，只取排序、必须引用代码证据。

盲评裁决（逐条 rubric 成对比较后的最终排序依据）
    门缺陷事件：fixture 缺少 laws/deprecations.log，三个 agent 彼此隔离却各自独立诊断出同一缺陷、给出同一最小修复——并行搜索顺带完成了对"陈述"本身的模糊测试。协议教训已入库：门必须在发布前对参照空实现跑过一次。

    这张图为什么能无锁运转

    契约不可变

    发布后永不编辑，只能废止追加。任何时刻针对某契约完成的工作永远有效，所以并行提交无需协调、无需合并仲裁——首个通过验收者胜。

    级联是真实执行的

    数学里组合免费（Curry–Howard）；软件里不是。父契约的验收是集成测试，在最后一个子契约关闭的瞬间真实运行——不过就把父级留在前沿。

    调度器是一个标量

    closability：关掉这个叶子能级联解决多少祖先。agent 从这个排序里自取工作，没有任务板，没有认领。
